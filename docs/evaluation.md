# 评测口径与诚实边界

## 合成检索评测

`scripts/report_retrieval.py` 只读取固定夹具 `tests/fixtures/retrieval_cases.json`，比较问题原文、
严格关键词、多路查询与 auto 候选发现等口径，报告 Recall@5、Precision@5、首条正确率和无答案
误召回率。生成结果写到 `outputs/`，不会打开正式数据库。

这些指标适合做代码改动前后的回归对照，但不能外推成真实会话表现：

1. 夹具规模小且由本项目维护，不是独立外部基准。
2. 它评估检索候选，不评估模型最终回答是否正确。
3. 客户端能否从自然语言中提取有效关键词不属于后端检索指标。
4. relaxed 候选仍需语义核对，不能因为出现在前五名就视为可信答案。

运行方式：

```powershell
.\.venv\Scripts\python.exe scripts\report_retrieval.py
```

## 正式数据库体检

`scripts/audit_memory.py` 通过 SQLite `mode=ro` 与 `PRAGMA query_only=ON` 读取一致快照，检查 scope、
来源字段、compact 投影和若干探针查询。默认输出不包含正文、标题、标签、会话编号或单条记录 ID。

```powershell
.\.venv\Scripts\python.exe scripts\audit_memory.py --db '.\data\memory.sqlite3'
```

体检里的“查询返回空比例”不是召回率。召回率需要先标注哪些记录与问题相关；没有标注答案时，只能
描述查询行为，不能把空结果自动判成错误。

审计结果仍可能描述个人数据的分布和来源覆盖，临时输出不要提交仓库。

## 发布或采纳检索改动的门槛

检索行为变更至少需要：

- 当前全量测试通过；
- 修改前后使用同一夹具和同一指标；
- Recall 提升不能以无答案误召回率上升为代价；
- scope、type、有效期、软删除与分页边界有独立回归测试；
- 新的近似路径能在诊断中被识别，而不是伪装成严格命中；
- 对正式库只做只读抽查，不使用个人数据反复调参后再把结果称作泛化能力。

## 后续方向

若要发布可横向比较的成绩，应接入来源明确、许可允许且能固定版本的公开中文长期记忆评测集，并把
数据准备、答案标注和计分脚本一并版本化。在此之前，仓库中的数字只表示本项目自己的回归基线。
