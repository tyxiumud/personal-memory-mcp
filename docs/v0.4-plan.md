# v0.4 候选计划：严格检索与诊断一致性

> 状态：阶段 1 已实施；严格中文检索仍是待评测提案。写进计划不表示实验已经决定上线。

## 已完成的两个一致性修复

### 精确查重不再依赖 source.trigger

非 supersedes 写入现在都执行活动精确重复检查，不再依赖 `source.trigger`。是否强制 trigger 字段属于
另一个写入治理问题，不与查重绑定。

### auto 回退明确报告 relaxed strategy

auto 回退实际返回结果时，顶层 `strategy` 现在明确设为 `relaxed`，同时保留原查询路数和 fallback
诊断；没有触发回退时 strict、browse、rrf_variants 保持原行为。

对应回归测试包括：

- 缺 trigger 的精确重复返回原 ID 和 `deduplicated=true`；
- auto 回退成功时 `strategy=relaxed` 且 `reason=relaxed_match`；
- 没有触发回退时 strict、browse、rrf_variants 保持原行为。

## 需要实验验证的严格中文检索改动

中文长查询按 bigram AND 组合时，跨词边界片段可能在当前范围内频率为零。例如“投资偏好”可能生成
“投资 / 资偏 / 偏好”，其中“资偏”让整条严格查询返回空。

候选方案是在严格检索组装 AND 前测量片段在当前 scope/type/有效期过滤下的文档频率，丢弃零频片段，
并在诊断中公开 `strict_dropped_fragments`。这不是无风险修复：删除用户真正输入但当前不存在的词，也
可能让剩余常见词产生误召回。因此它必须作为单独实验，不能与前两个一致性修复捆绑上线。

边界要求：

- 所有片段均为零频时仍返回 `no_lexical_match`，不能退化为 browse；
- 丢弃操作不能放宽 scope、type、有效期或软删除过滤；
- 英文词和单字查询保持原行为；
- 诊断必须列出被丢弃片段；
- strict Recall@5 提升的同时，无答案误召回率不能上升。

## 实施顺序

1. 已完成查重和 strategy 修复及最小回归测试。
2. 实验前保存当前合成夹具报告作为基线。
3. 单独实现严格中文片段实验，生成新的检索报告。
4. 只有预先定义的采纳门槛同时满足时保留实验；否则回退该实验，不影响已完成的一致性修复。
5. 通过全量测试、Ruff、三端连接探针和正式库只读体检后，才更新正式行为文档。

基线和候选报告均由 `scripts/report_retrieval.py` 使用固定夹具生成，不读取正式数据库。详细评测边界见
`evaluation.md`。

## 本阶段不做

`committed` 写入闸门、批量写入、tags 过滤、embedding、关系图和自动 consolidation 不纳入此计划。
它们会改变工具契约或系统边界，应单独设计和验收。
