# v0.4 中文严格检索实验记录

2026-10-04。按 [v0.4 计划](v0.4-plan.md) 在同一份合成夹具上比较修改前后；基线代码为
`25c20ae`，夹具为 `tests/fixtures/retrieval_cases.json`（20 条 tuning、14 条 development、
16 条 validation）。报告脚本只建立临时合成数据库，不打开正式记忆库。以下数字是后端候选回归结果，
**不是**真实对话准确率，也不是独立盲测。

完整的固定夹具报告：[修改前基线](../outputs/v0.4-baseline.md)、
[宽泛方案（已拒绝）](../outputs/v0.4-candidate.md)、[收窄方案](../outputs/v0.4-narrow.md)。

## 先试过、但拒绝的方案

把严格查询中所有范围内零频片段都丢掉，validation 的原文查询 Recall@5 从 0% 升到 80%，
但 6 条无答案用例新增 1 条误召回（0% → 16.7%）：问“投资账户密码”时返回了投资偏好记录。
这不符合计划中的采纳门槛，因此没有保留这条宽泛规则。

## 保留的窄规则

仅对 4～5 个连续汉字的短词组，在原严格 AND 查询无结果时，检查当前 scope、type、有效期和遗忘
过滤后的片段文档频率。首尾双字片段必须都出现，至少一个首尾片段不能是范围内的通用片段；只删除
零频的**中间**双字片段，再对保留片段做 AND。英文、单字、长问句、首尾片段缺失和全为通用片段的
查询保持原行为。它不是语义检索；即使命中也需要核对记录正文和来源。

| 合成集合与路径 | 修改前 Recall@5 | 修改后 Recall@5 | 无答案误召回（前 → 后） |
| --- | ---: | ---: | ---: |
| development，严格关键词 | 55.6% | 66.7% | 0/5 → 0/5 |
| tuning，严格关键词 | 80.6% | 86.1% | 0/2 → 0/2 |
| validation，长问句原文 | 0% | 0% | 0/6 → 0/6 |

development 的“投资偏好”从空结果变为 1 条候选。validation 长问句没有改善，仍需客户端提取关键词
或使用 `search_mode="auto"` 的候选发现；auto 在该集合的 6 条无答案用例中仍有 1 条误召回，
不能直接把宽松候选当答案。

剪除发生时，`retrieval.strategy="strict_pruned"`（多路时仍为 `rrf_variants`）、
`retrieval.strict_dropped_fragments` 列出被剪片段，记录标记 `match_quality="pruned"`。
只读正式库体检中，通用探针“投资偏好”的候选数由 0 变为 1，10 条探针的空结果由 5 条变为 4 条；
探针没有人工标注相关答案，**不能**把这组数字叫作召回率。正式库未用于调阈值，也没有被修改。

回归覆盖范围、类型、有效期、软删除、分页、已有精确命中、英文和单字行为；脚本的合成数据库改为
独立临时目录，避免覆盖先前生成的本地报告数据库。三端连接探针只能验证 MCP 启动和读取，不能
证明真实 Agent 对话会自动写入。真实客户端读写验收仍是单独待办。
